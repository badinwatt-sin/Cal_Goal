# Cal Goal

เว็บแอปนับแคลอรี่ ติดตามอาหาร พลังงาน และเป้าหมายน้ำหนัก ภาษาไทย ไม่ต้องล็อกอิน

- คำนวณ BMR / TDEE (Mifflin–St Jeor) และงบแคลต่อวัน
- ฐานข้อมูลอาหารไทยและนานาชาติ 230+ รายการ (ค่าประมาณเฉลี่ย)
- บันทึกออกกำลังกาย (MET) และก้าวเดิน ตั้งเป้าน้ำหนักรายสัปดาห์/เดือน/ปี
- อวตารการ์ตูนปรับแต่งได้ มีท่าทางตามสถานะของวัน
- ข้อมูลเก็บในเบราว์เซอร์ (localStorage) พร้อมสำรอง/นำเข้าไฟล์ JSON
- เลือกธีมสว่าง / มืด / ตามเครื่องได้ในแท็บโปรไฟล์ ค่าเริ่มต้นตามการตั้งค่าอุปกรณ์และเปลี่ยนตามทันที โดยจำตัวเลือกไว้ในเบราว์เซอร์แต่ละเครื่อง

## หน้าตาและการใช้งาน
- ดีไซน์ใหม่ใช้พื้นครีม สีเขียว และตัวอักษรไทยแนวตั้ง อ่านได้ทั้งธีมสว่างและมืด จัดลำดับหน้า วันนี้ → กิจกรรม → เป้าหมาย → โปรไฟล์ พร้อมปุ่มบันทึกกลางแถบเมนู
- หน้าวันนี้แสดงพลังงานคงเหลือ ปุ่มเพิ่มอาหาร และสมุดมื้ออาหารก่อนกราฟ รายละเอียดวิธีคำนวณกดเปิดอ่านได้ เลือกวันที่ย้อนหลังได้ทั้งหน้าวันนี้และกิจกรรม
- โปรไฟล์แสดงข้อมูลสำคัญและทางเข้าสตูดิโอตัวละคร มีธีม ข้อมูลนาฬิกา และเครื่องมือสุขภาพ ส่วนอวตารแบบภาพ สำรองข้อมูล และการตั้งค่าขั้นสูงกดขยายเมื่อต้องการ
- ค้นหาและแก้ฟอร์มโดยคงตำแหน่งพิมพ์ไว้ ตัวจับเวลาฟาสต์อัปเดตเฉพาะตัวเลข มีปุ่มเลิกทำหลังลบอาหารหรือกิจกรรม และรองรับคีย์บอร์ดในหน้าต่างบันทึก
- สี ระยะห่าง ตัวอักษร และองค์ประกอบหน้าจออยู่ใน `app.css` ตัวละคร Beep อยู่ในพื้นที่ข้างหัวข้อหน้า ไม่บังปุ่มบันทึก ลดขนาดในหน้ากิจกรรม เป้าหมาย และโปรไฟล์ และพักการเคลื่อนไหวขณะกรอกฟอร์มหรือเลื่อนพ้นจอ

## เครื่องมือประจำวันและ Character Studio
- **น้ำดื่ม:** กดเพิ่ม 150 / แก้วที่ใช้บ่อย / 500 มล. บนหน้าวันนี้ หรือเปิดประวัติเพื่อใส่จำนวนเอง ลบ/เลิกทำ และตั้งเป้าส่วนตัว ข้อมูลลงวันที่ที่เลือก ไม่ปนกับยอดก้าวหรือพลังงานจากนาฬิกา
- **เมนูโปรด:** กดดาวในหน้าปรับจำนวนอาหาร คลังเก็บชื่อ หน่วย แหล่งข้อมูล และโภชนาการต่อหน่วย แม้เมนูชื่อเหมือนกันแต่หน่วยหรือแหล่งต่างกันก็เก็บแยกได้ เปิดจากไอคอนคลังในหัวมื้ออาหารหรือหมวด “โปรด” ในหน้าค้นหา
- **มื้อประจำ:** ใต้รายการของแต่ละมื้อ กด “เก็บมื้อนี้ไว้ใช้ซ้ำ” ตั้งชื่อ แล้วเรียกใช้จากคลัง ปรับจำนวนชุดและเลือกมื้อก่อนยืนยัน รายการใหม่มี ID แยกจากต้นฉบับ ไม่เก็บรูปภาพซ้ำในคลัง การลบคลังไม่ลบบันทึกประจำวัน
- **เป้าสารอาหาร:** เลือกสมดุล / เน้นโปรตีน หรือกำหนดสัดส่วนเองรวม 100% คิดกรัมจากเป้าพลังงานประจำวันก่อนรวมกิจกรรม (โปรตีนและคาร์บ 4 kcal/ก., ไขมัน 9 kcal/ก.) เมนูที่ไม่ทราบสารอาหารมีข้อความบอก ไม่ถือว่าเป็นข้อมูลครบถ้วน
- **สรุป 7 วัน:** ดูพลังงานและโปรตีนเฉลี่ยเฉพาะวันที่มีบันทึก ก้าวและนาทีออกกำลังรวม น้ำดื่ม น้ำหนัก และเหรียญจากการสะสมวันที่ดูแลตัวเอง วันว่างไม่ถูกคิดเป็นการกิน 0 kcal และไม่ใช้เป้าปัจจุบันไปตัดสินการทำได้ตามเป้าในอดีต
- **Character Studio:** เปิดการ์ดตัวละครในโปรไฟล์ มีลุคเริ่มต้น 4 แบบ ชุด 4 แบบ ทรงผม 5 แบบ สีผิว สีเสื้อ/กางเกง/ผม แว่น หมวก หูฟัง ฉาก และท่าทาง พรีวิวมนุษย์ 3D จริง ลากหรือใช้ปุ่มลูกศรเพื่อหมุน Space เพื่อโบกมือ เลือกสุ่ม/ย้อนกลับได้ กดบันทึกเมื่อพอใจ ยกเลิกไม่เปลี่ยนลุคที่บันทึกไว้
- ตัวละครใช้ `avatar-3d.js` กับ Three.js ที่มีในแอป มีภาพ 2D สำรองเมื่อ WebGL ใช้ไม่ได้ เคารพการลดการเคลื่อนไหว และหยุดวาดเมื่อมองไม่เห็น ใช้ตัวละครเป็นรูปโปรไฟล์ได้โดยยังเก็บภาพ/อีโมจิเดิมไว้ การสุ่มเปลี่ยนเฉพาะหน้าตาตัวละคร ไม่เปลี่ยนเพศ ส่วนสูง น้ำหนัก หรือแผนสุขภาพ
- ข้อมูลใหม่เก็บใน localStorage/ไฟล์สำรองเดิม และซิงก์ผ่านบัญชี Supabase เดิมเมื่อเข้าสู่ระบบ กฎข้อมูล/การย้ายข้อมูลเก่าอยู่ใน `wellness.js` รูปแบบหน้าจอเพิ่มเติมใน `features.css` ไม่ต้องสร้างตารางหรือสมัครบริการเพิ่ม

แนวฟีเจอร์อ้างอิงจากหน้าทางการของ [Lifesum](https://lifesum.com/features/), [YAZIO](https://www.yazio.com/en/calorie-counter) และ [Cronometer](https://cronometer.com/features/custom-meals-and-recipes.html) โดยเลือกส่วนที่ทำงานได้กับเว็บแอปนี้

## ใช้งาน
เปิด https://calgoal.vercel.app หรือรัน `python3 -m http.server 8000` ในโฟลเดอร์โปรเจกต์ แล้วเปิด http://localhost:8000 ไม่ต้อง build การแสดงผล 3D และตัวอ่านไฟล์สุขภาพต้องเปิดผ่าน HTTP(S)

## บันทึกข้อมูลจากนาฬิกาด้วยตัวเอง
- เปิด โปรไฟล์ → บันทึกข้อมูลจากนาฬิกา หรือ กิจกรรม → บันทึกข้อมูลจากนาฬิกา แล้วกรอกยอดจาก Apple Health, Zepp หรือ Samsung Health รองรับก้าวเดิน พลังงานกิจกรรมรวมรายวัน และประวัติน้ำหนัก
- เลือกไฟล์ Apple Health `export.zip` / `export.xml` ได้โดยตรง หรือ CSV สรุปรายวัน เลือกแหล่งข้อมูลหนึ่งแหล่งต่อประเภทและช่วงวันที่ แล้วดูตัวอย่างก่อนยืนยัน ไฟล์ดิบจากผู้ผลิตไม่ได้มีรูปแบบเดียวกันทั้งหมด สำหรับ Samsung ให้เลือก CSV สรุปก้าวรายวันจาก ZIP ที่แตกแล้ว หากอ่านไม่ได้ให้กำหนดคอลัมน์ CSV หรือกรอกยอด
- CSV ตัวอย่างหัวคอลัมน์: `date,steps,active_kcal,weight_kg` วันที่ `YYYY-MM-DD` และเว้นข้อมูลที่ไม่ต้องการได้ CSV ถือเป็นยอดรายวัน หากซ้ำวันเดียวกันใช้ยอดก้าว/พลังงานที่มากที่สุด น้ำหนักใช้แถวสุดท้าย เลือกหน่วยปอนด์ได้ในหน้าตัวอย่าง ห้ามใช้ total calories รวมพลังงานพักเป็น active calories
- ค่าที่ยืนยันใช้แทนค่าของวันที่ตรงกัน ไม่บวกซ้ำเมื่อเลือกไฟล์เดิม น้ำหนักเพิ่มเฉพาะประวัติ ไม่เปลี่ยนน้ำหนักโปรไฟล์ หากมีพลังงานกิจกรรมรายวัน งบแคลใช้ยอดนี้แทนผลรวมประมาณจากก้าวและรายการออกกำลังของวันนั้น กด “กลับไปใช้พลังงานประมาณ” ในแท็บออกกำลังกายเพื่อยกเลิกยอดพลังงานของวัน
- อ่านไฟล์ใน Web Worker บนเครื่อง เก็บเฉพาะยอดที่ยืนยัน (ซิงก์เข้าบัญชีเดิมเมื่อเข้าสู่ระบบ) ZIP/XML ไม่เกิน 100 MB, XML หลังคลาย ZIP ไม่เกิน 512 MB, CSV ไม่เกิน 10 MB/20,000 แถว ใช้ fflate 0.8.2 ที่เก็บใน `assets/vendor/fflate/` พร้อม MIT License การอ่านไฟล์ต้องเปิดผ่าน HTTP(S) เช่นเว็บที่ Deploy แล้ว
- รัน `npm test` เพื่อตรวจ parser การแยกแหล่งข้อมูล หน่วย วันที่ และการนำเข้าซ้ำ โดยไม่ต้องติดตั้งแพ็กเกจทดสอบเพิ่มเติม (Node.js 22 ขึ้นไป)

## เปิดใช้การล็อกอินและซิงก์ข้อมูล (Supabase, ไม่บังคับ)
ถ้าไม่ตั้งค่า แอปทำงานแบบไม่ล็อกอิน (เก็บข้อมูลในเครื่อง) ถ้าตั้งค่า ผู้ใช้จะเห็นหน้าเข้าสู่ระบบก่อน (หรือเลือกใช้โดยไม่ล็อกอินได้) และข้อมูลซิงก์ข้ามเครื่อง
1. สร้างโปรเจกต์ที่ https://supabase.com แล้วรัน `supabase/schema.sql` ใน SQL Editor (สร้างตาราง `user_data` พร้อม Row Level Security ให้แต่ละคนเข้าถึงได้เฉพาะแถวของตัวเอง)
2. Authentication → Providers: เปิด **Email** (magic link) และ/หรือ **Google** (ต้องสร้าง OAuth Client ใน Google Cloud Console แล้วใส่ redirect URI `https://<project-ref>.supabase.co/auth/v1/callback`)
3. Authentication → URL Configuration: ตั้ง **Site URL** เป็นลิงก์แอปบน Vercel และเพิ่มลิงก์เดียวกันใน **Redirect URLs**
4. แก้ `config.js` ใส่ `supabaseUrl` และ `supabaseAnonKey` (Project Settings → API → anon public) แล้ว push
5. (ทางเลือก) อีเมลเริ่มต้นของ Supabase ส่งได้จำกัดจำนวนต่อชั่วโมง ถ้าเปิดสาธารณะควรตั้ง SMTP ของตัวเอง (Authentication → SMTP Settings)

ข้อมูลที่ซิงก์: โปรไฟล์ เป้าหมาย บันทึกอาหาร/ออกกำลังกาย น้ำหนัก (ไม่ซิงก์รูปอาหาร) เมื่อขัดแย้งกัน ฝั่งที่แก้ไขล่าสุดชนะ

## ตั้งค่า AI ประเมินแคลจากรูป (Vercel + Gemini)
1. สร้าง API key ที่ https://aistudio.google.com/apikey
2. Vercel → Project → Settings → Environment Variables เพิ่ม `GEMINI_API_KEY` (ไม่บังคับ: `GEMINI_MODEL` ค่าเริ่มต้น `gemini-3.5-flash-lite`, `GEMINI_FALLBACK_MODELS` โมเดลสำรองคั่นด้วย `,` ค่าเริ่มต้น `gemini-flash-lite-latest,gemini-flash-latest`, `DAILY_LIMIT` ค่าเริ่มต้น 20 รูป/IP/วัน, `TEXT_LIMIT` ค่าเริ่มต้น 60 ครั้ง/IP/วัน สำหรับประเมินจากชื่อเมนู)
   - ถ้าโมเดลหลักเต็มโควตา ล่ม หมดเวลา หรือตอบไม่เป็น JSON ระบบจะลองโมเดลสำรองให้อัตโนมัติ (โควตาฟรีแยกต่อโมเดล)
3. Redeploy

ฟังก์ชันอยู่ที่ `api/estimate.js` ตัวนับต่อ IP เก็บในหน่วยความจำ เป็นเพียงด่านกันใช้เกินแบบหยาบ ถ้าเปิดสาธารณะจริงควรเพิ่มที่เก็บภายนอก (เช่น Upstash Redis) และตั้งเพดานงบในบัญชี Google

## PWA และ Beep
- Beep เป็นโมเดล WebGL 3D ที่มีข้อต่อแขนขา โบกมือ เดินย่ำเท้า กระโดด และกะพริบตาได้ กดปุ่ม ↟ เพื่อสั่งกระโดด กดตัวละครเพื่อเปิดแชต โหลด Three.js 0.180.0 จากไฟล์ในแอป (`assets/vendor/three/`, MIT) และใช้ภาพเดิมเมื่อเครื่องไม่รองรับ WebGL หยุดเรนเดอร์เมื่อซ่อนตัวละครหรือสลับแอป และเคารพการตั้งค่าลดการเคลื่อนไหวของเครื่อง
- ติดตั้งเป็นแอปได้ (manifest + service worker) ดูปุ่ม/วิธีติดตั้งในแท็บโปรไฟล์
- Beep ผู้ช่วยข้างหัวข้อหน้า (แชตเปิดค้างระหว่างใช้แอป มีคำแนะนำตามสถานการณ์; แชต AI) เรียก `/api/chat` ใช้ `GEMINI_API_KEY` ตัวเดียวกับ `/api/estimate` (ไม่บังคับ: `CHAT_LIMIT` ค่าเริ่มต้น 30 ข้อความ/IP/วัน)

## ฐานข้อมูลอาหาร
- เมนูหลักในแอป: ค่าประมาณต่อหน่วยเสิร์ฟ (อยู่ใน `index.html`)
- `foods-th.js`: 633 เมนูจากกรมอนามัย 2561 (ส่วนใหญ่ต่อ 100 ก.) และฉลาก Nissin สร้างจาก `data/thai_food_calories_633.csv` ด้วย `python3 data/build_foods_th.py data/thai_food_calories_633.csv`
- `data/foods_th_review.csv`: เทียบชื่อเดิม (OCR) กับชื่อที่แก้แล้ว ไว้ตรวจทาน
- `foods-more.js`: ~670 เมนูยอดนิยมเพิ่มเติม (สตรีทฟู้ด ร้านสะดวกซื้อ คาเฟ่ ฟาสต์ฟู้ด ญี่ปุ่น เกาหลี คลีน เครื่องปรุง) ค่าประมาณต่อหน่วยเสิร์ฟ มีโปรตีน/ไขมัน และคำค้นอื่น — แก้ที่ `data/foods_more.txt` แล้วรัน `python3 data/build_foods_more.py`
- การค้นหาทนคำผิด: ไม่สนช่องว่าง/วรรณยุกต์ รู้จักคำสะกดยอดนิยม (กระเพรา, ผัดไท, สเต๊ก…) คำเรียกอื่น (ชาเย็น, ไอติม, เซเว่น…) และภาษาอังกฤษ ถ้าไม่เจอจะแสดงเมนูใกล้เคียง + ปุ่มให้ AI ประเมินจากชื่อ (ผลถูกจำไว้ใน “ของฉัน”)

## แจ้งเตือนฟาสต์ครบ (ไม่บังคับ)
ตอนแอปเปิดอยู่จะเตือนได้เลย ถ้าอยากให้เด้งแม้ปิดแอป ตั้งค่าใน Vercel → Environment Variables:
- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` สร้างด้วย `npx web-push generate-vapid-keys` (ห้ามใส่ private key ใน repo)
- `QSTASH_TOKEN` จาก console.upstash.com → QStash (ฟรี 500 ข้อความ/วัน; ถ้า Upstash ให้ URL ภูมิภาคมาด้วย ใส่ `QSTASH_URL`)
- iPhone ต้องเพิ่มแอปไปที่หน้าจอโฮมก่อน (iOS 16.4+) จึงจะรับแจ้งเตือนได้
